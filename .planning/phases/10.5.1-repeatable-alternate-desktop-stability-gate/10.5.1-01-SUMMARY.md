# Phase 10.5.1 Plan 01: Summary

The repeatability proof now targets one named worker directly instead of gambling on normal session routing.

## Accomplishments

- Added `POST /internal/workers/:id/validation-session` so a validation run can claim one ready worker deterministically.
- Added `SessionService.createPinnedSession(...)` so control-api can activate that validation session on the named worker without using the public queue.
- Reworked `test-host-worker-relay.ps1` to use the pinned validation session instead of stopping the rest of the pool just to hit the target worker.
- Kept the proof honest: it still waits for real fresh-chat bootstrap, sends a real relay prompt, verifies the assistant reply, and tears the validation session down cleanly.
- Fixed a live-only bug found during execution: the pinned session route now returns a top-level `sessionId`, so the proof script can always poll the right session.

## Key Decisions

- Deterministic validation belongs in an internal worker-scoped route, not in the public session API.
- Routing failures should stay distinguishable, but they should stop masking real bootstrap/auth problems on the primary proof path.

## Verification

- `cmd /c npm.cmd test --prefix services/control-api`
- `cmd /c npm.cmd run build --prefix services/control-api`
- PowerShell parser check for `infra/host-worker/test-host-worker-relay.ps1`

## Residual Risk

- The proof path is now cleaner, but it can still reveal genuine ChatGPT runtime failures such as `bootstrap_navigation_failed` or `bootstrap_auth_required`.
