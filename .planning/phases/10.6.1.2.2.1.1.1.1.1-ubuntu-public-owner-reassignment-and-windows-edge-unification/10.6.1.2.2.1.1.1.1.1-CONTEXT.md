# Phase 10.6.1.2.2.1.1.1.1.1 Context

## Summary

This phase is the preserve-first follow-up after the exact blocker was reduced to:

- `split_ingress_owner_conflict`

Previous phases already proved:

- the preserved Windows browser block with 9 live accounts remains intact
- Windows `Caddy` is still alive on the LAN-side host `192.168.88.250`
- public `77.66.186.75` currently lands on Ubuntu `nginx`
- the wrong Ubuntu-side public owner is the real blocker before `Phase 11`

So this phase is no longer about proving browsers, proving TLS in isolation, or re-checking random worker health.

It is about one narrow question:

- how do we preserve-first unify the real public owner path so that `77.66.186.75` serves one deliberate API contract instead of splitting between Ubuntu `nginx` and Windows `Caddy`?

## Current Truth

- Preserved Windows browser block host:
  - `192.168.88.250`
- Public IP under test:
  - `77.66.186.75`
- Current real public owner:
  - Ubuntu `nginx`
- Current preserved Windows edge:
  - `Caddy` on the Windows host, reachable on the LAN-side path
- Current exact blocker:
  - `split_ingress_owner_conflict`
- Current intended safe Windows-side API topology:
  - `Caddy -> 127.0.0.1:4011` for shadow
  - `Caddy -> 127.0.0.1:4010` for promoted
  - raw `4040` and worker-agent ports remain private

## Locked Decisions

- Preserve-first remains higher priority than speed to green.
- Do not mass-restart, mass-relogin, or broadly revalidate all 9 workers.
- Keep `shared-6` as the only default canary unless owner-path proof fails before worker chat is even relevant.
- Do not expose raw `4040`, worker-agent ports, or raw public `:4010` as a shortcut.
- Do not treat Windows-local success as proof of the real public contract.
- Do not rewrite the Windows browser block broadly if the blocker still belongs to Ubuntu public ownership.

## Primary Candidate For This Phase

The planning default for this phase is:

- keep Ubuntu as the deliberate public owner of `77.66.186.75`
- remove or override the conflicting Ubuntu-side ownership that currently sends `77.66.186.75` into the wrong responder
- proxy the deliberate API routes onward to one Windows-side internal edge path

Why this is the recommended default:

- `77.66.186.75` already terminates on Ubuntu today
- changing Ubuntu-side public ownership is a smaller preserve-first move than moving the public IP contract directly onto the Windows host
- it keeps the 9 live accounts isolated from the public-owner fix

## Phase Goal

End this phase with one truthful outcome:

- `safe_to_promote`
- `safe_but_hold`
- `hold_preserve_accounts`

The phase is successful if it leaves no ambiguity about:

1. who owns public `77.66.186.75`
2. whether Ubuntu can safely serve as the deliberate public owner while unifying the Windows API edge behind it
3. whether `Phase 11` can resume or must stay blocked by one exact non-browser blocker
