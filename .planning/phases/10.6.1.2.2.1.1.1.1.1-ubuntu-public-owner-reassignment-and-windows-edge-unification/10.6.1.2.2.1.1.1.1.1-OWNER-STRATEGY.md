# 10.6.1.2.2.1.1.1.1.1 Owner Strategy

- Phase: `10.6.1.2.2.1.1.1.1.1`
- Date: `2026-03-31`
- Status: `captured`

## Short Report

The preserve-first owner strategy is now explicit.

Simple explanation:

- Ubuntu already owns the real public IP `77.66.186.75`
- the wrong piece is not Ubuntu itself, but the competing `ascii-art` IP-owner path
- Windows `Caddy` is already alive on `192.168.88.250`
- Ubuntu can already reach the preserved Windows public API over plain HTTP if it forwards `Host: 77.66.186.75`

That means the smallest safe move is:

1. keep Ubuntu as the real public owner
2. remove `77.66.186.75` from the conflicting `ascii-art` vhost
3. let Ubuntu own public `80/443` for the API contract
4. proxy the public API routes onward to the preserved Windows edge over LAN HTTP

## Exact Upstream Contract Assumptions

Verified from Ubuntu before live reassignment:

- `http://192.168.88.250/healthz` -> `308` with `Server: Caddy`
- `http://192.168.88.250/healthz` plus `Host: 77.66.186.75` -> `200`
- `http://192.168.88.250/v1/models` plus `Host: 77.66.186.75` -> reachable through the preserved Windows edge
- `POST /v1/chat/completions` through the same HTTP+Host path can succeed on canary `shared-6`

Current non-goal for the upstream hop:

- Ubuntu does **not** need to consume Windows over HTTPS for this phase
- direct Ubuntu -> Windows TLS currently fails with `tlsv1 alert internal error`
- preserve-first unification therefore uses:
  - `Ubuntu nginx -> http://192.168.88.250`
  - forced upstream `Host: 77.66.186.75`

## Preserve-First Owner Model

### Public owner

- real public owner remains Ubuntu `nginx`
- public client contract remains on `77.66.186.75`

### Preserved Windows edge

- Windows `Caddy` remains the browser-block edge
- Windows continues to hide:
  - raw `4040`
  - worker-agent ports
  - raw `:4010`

### Unified contract shape

- `http://77.66.186.75/healthz` -> Ubuntu -> Windows edge
- `http://77.66.186.75/api/relay/*` -> Ubuntu -> Windows edge
- `http://77.66.186.75/v1/*` -> Ubuntu -> Windows edge
- `http://127.0.0.1:8080/*` on Ubuntu remains the Linux local relay/operator path

## Unrelated Hostnames To Preserve

The `ascii-art` hostnames stay intact:

- `main.ascii-art.ru`
- `www.ascii-art.ru`

Only the raw public IP ownership is reassigned away from that vhost.

## Rollback-Safe Baseline

Before live reassignment:

- back up `/etc/nginx/sites-available/ascii-art.conf`
- back up `/etc/nginx/sites-available/owmcgp-remote-relay.conf`
- keep the 9-account Windows browser block untouched
- keep canary scope at `shared-6`
- keep raw `4040`, worker-agent ports, and raw public `:4010` private

Rollback means:

1. restore the previous Ubuntu `ascii-art.conf`
2. restore the previous Ubuntu `owmcgp-remote-relay.conf`
3. `nginx -t`
4. reload `nginx`

## Strategy Decision

Chosen model:

- `Ubuntu public owner -> Windows edge over LAN HTTP with forced Host header`

Why this wins preserve-first:

- it avoids another broad public-IP move
- it preserves the already-working Windows browser block
- it fixes the exact blocker at the real owner layer
- it does not require exposing any additional Windows internals publicly
