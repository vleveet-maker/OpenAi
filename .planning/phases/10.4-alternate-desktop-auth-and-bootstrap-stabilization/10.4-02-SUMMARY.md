# Phase 10.4 Plan 02: Summary

The alternate-desktop bootstrap path now treats “Temporary Chat opened” as an intermediate step instead of a false finish line.

## Accomplishments

- Added `composer_not_ready` and made bootstrap success depend on a visible prompt composer after model selection.
- Centralized composer readiness selectors alongside Temporary Chat confirmation and onboarding selectors in the bootstrap selector map.
- Made the bootstrap runner step-aware, with clearer `step` and `stepDetail` evidence for auth loss, temporary confirmation drift, model selection issues, and missing composer surfaces.
- Updated `manual-auth/complete` so the worker returns as `validationPending: true` with the reason `manual login completed; alternate desktop validation pending`.
- Extended the internal admin page to show `lastBootstrapFailureCode` and `lastBootstrapStep`, and to distinguish auth-required states from bootstrap drift.

## Key Decisions

- A non-visible runtime is not rollout-usable until the same browser surface reaches a real prompt composer.
- Manual login completion is now an operator handoff into validation, not a claim that alternate-desktop is already healthy.

- `cmd /c npm.cmd test --prefix services/control-api`

## Residual Risk

- The control plane is now honest about validation state, but Phase 10.4 still needs bounded live proof to show whether `wife`, `dad`, or `shared-1` can actually reach `phase11Ready=true`.
