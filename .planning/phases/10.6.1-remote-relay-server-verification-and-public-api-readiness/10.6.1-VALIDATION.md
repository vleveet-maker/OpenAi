# Phase 10.6.1 Validation

## Scope

This phase is valid only if it proves three different things explicitly:

1. server truth
2. worker/session truth
3. public API truth

## Requirement Mapping

| Requirement | Covered By | Expected Evidence |
|-------------|------------|------------------|
| EXTAPI-01 | 10.6.1-01 | repeatable server verification script and runbook |
| EXTAPI-02 | 10.6.1-02 | worker-by-worker remote smoke matrix |
| EXTAPI-03 | 10.6.1-03 | deliberate ingress config and external smoke |
| EXTAPI-04 | 10.6.1-03 | public API docs, auth truth, example requests |

## Verification Gates

### Gate 1: Server Truth

- service enabled/active check exists
- local relay health check exists
- ingress health truth exists
- topology truth is surfaced in docs or script output

### Gate 2: Worker Truth

- all six official workers are audited:
  - `dad`
  - `wife`
  - `shared-1`
  - `shared-2`
  - `shared-3`
  - `shared-4`
- each worker gets an explicit result class
- the audit runs through the real remote relay topology, not only local browser inspection

### Gate 3: Public API Truth

- one deliberate external ingress path exists
- public callers use only intended relay routes
- auth model is documented
- docs contain at least one fresh-dialog and one continuing-dialog example

## Expected Artifacts

- `.planning/phases/10.6.1-remote-relay-server-verification-and-public-api-readiness/10.6.1-SERVER-VERIFICATION.md`
- `.planning/phases/10.6.1-remote-relay-server-verification-and-public-api-readiness/10.6.1-WORKER-MATRIX.md`
- `docs/remote-relay-server.md`
- external ingress config artifact in `infra/remote/`

## Exit Rule

Do not mark this phase complete unless all three truths are explicit.

It is acceptable to end with a partial result if:

- the server verification path exists
- the worker matrix exists
- and the public ingress step ends with a precise blocker instead of a vague "network issue"
