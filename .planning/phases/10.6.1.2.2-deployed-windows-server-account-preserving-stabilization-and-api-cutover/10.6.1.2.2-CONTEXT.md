# Phase 10.6.1.2.2 Context

## Summary

This phase is not about packaging a fresh Windows browser block.

That packaging work is already done. The new truth is operational:

- one target Windows Server already runs the browser block
- nine ChatGPT accounts are already logged in there
- the repo code can be improved, but the deployed server is no longer disposable

So the correct follow-up is a preserve-first stabilization and API-cutover phase, not a blind redeploy.

## Current Truth

- The Linux relay/API boundary already exists and remains deliberate.
- One Windows Server already holds a deployed browser block with nine logged-in accounts.
- The code running on that server comes from the GitHub repo rather than this exact local worktree.
- The current local repo may lag behind the deployed 9-slot server code, so execution must reconcile deployed truth against repo truth before any uplift.
- The current direct local machine proof remains useful historical evidence, but it is no longer the only runtime truth that matters.
- The deployed Windows Server block must now be treated as the highest-value browser-runtime environment because it already contains live logged-in accounts.

## Locked Decisions

- Do not delete, reset, or overwrite the deployed browser profiles as a first step.
- Do not clear cookies, storage, or crash-recovery state blindly on the Windows Server.
- Do not force a mass relogin of all nine accounts just because repo code changed.
- Do not run duplicate browser processes against the same profile paths.
- Do not do a blind in-place overwrite from repo to server without freeze-point evidence and rollback.
- Use staged uplift: freeze and audit first, then one-worker canary, then small subset, then full pool.
- If one worker already arrives broken before the phase starts, record that as pre-existing truth instead of silently normalizing it into "all workers needed relogin".

## Phase Goal

Safely evolve the already-deployed Windows Server browser block so it can serve the public API path without risking the nine live logged-in accounts already on that host.
