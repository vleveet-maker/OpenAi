# Phase 10.6.1.2.2 Validation

## Validation Focus

This phase is valid only if it treats the deployed Windows Server as a preserve-first environment.

It is invalid if it:

- overwrites live profiles before taking a freeze point
- clears cookies or storage as a default repair action
- turns "mass relogin" into the assumed happy path
- claims API cutover readiness without a staged canary and rollback path

## Required Evidence

- deployed-server audit artifact
- deployment provenance or package-version artifact
- backup or rollback contract for the live profiles
- canary and subset validation evidence
- final nine-worker matrix
- final cutover verdict

## What Must Be True Before Closeout

- the deployed Windows Server block is version-mapped truthfully
- the repo has an explicit non-destructive operating contract
- canary uplift exists before any full-pool touch
- public API cutover has a shadow path and rollback path
- the final verdict says either `safe_to_promote`, `safe_but_hold`, or `hold_preserve_accounts`

## Recommended Checks

- deployed host provenance capture: package manifest, git head, or equivalent build marker
- worker-by-worker matrix on the deployed Windows Server
- local or shadow public API probe before edge promotion
- explicit rollback dry-run or rollback checklist review
