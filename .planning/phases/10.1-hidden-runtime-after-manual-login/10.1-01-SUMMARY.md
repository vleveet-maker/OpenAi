# Phase 10.1 Plan 01: Summary

The host-native worker path now has a real two-mode runtime instead of always opening a desktop browser and calling it "native."

## Accomplishments

- Split worker-agent launch into explicit `visible_auth` and `hidden_runtime` modes.
- Made hidden runtime launch through the worker-agent itself with `headless: true`, durable profile reuse, and proxy propagation.
- Added runtime-mode, headless, CDP-attachment, and proxy-configured fields to worker-agent health payloads.
- Refactored host PowerShell scripts so visible auth is explicit and hidden runtime no longer launches an external browser window.
- Updated host-controller start contracts so pool start defaults to `hidden_runtime`, while direct worker start can still request `visible_auth`.
- Added automated coverage for the worker-agent runtime split and for host-controller hidden-runtime defaults.

## Key Decisions

- Treat hidden runtime as a first-class launch path, not as a minimized visible browser.
- Reuse the same durable profile sequentially across visible auth and hidden runtime rather than creating a separate browser stack.
- Keep `startPool()` hidden by default so routine household operation stops opening windows on the operator desktop.

## Verification

- `cmd /c npm.cmd test --prefix workers/agent`
- `cmd /c npm.cmd run build --prefix workers/agent`
- `cmd /c npm.cmd test --prefix services/host-controller`

## Residual Risk

- This plan establishes the runtime split and the hidden default, but it does not by itself prove that a manually authenticated profile can survive the full visible-to-hidden handoff against the current ChatGPT UI. That live gate is handled by the later validation probe and rollout smoke work.
