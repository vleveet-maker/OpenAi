## Manual-Only Verifications

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Visible manual auth can still be opened intentionally for one worker | HIDE-01 | Requires a real interactive browser window and live ChatGPT login state | From internal admin, trigger visible login for one worker and confirm a real Edge or Chrome window opens only for that requested worker |
| After completing manual auth, the same worker returns in hidden runtime without any visible browser window | HIDE-01, HIDE-02 | Desktop-window visibility and hidden browser state are host-specific | Complete login, trigger the hidden transition, verify no browser window remains visible, then confirm worker `/health` reports hidden mode |
| Hidden runtime can relay without reopening a visible browser window | HIDE-02 | Requires live browser + ChatGPT state | Run the hidden-runtime relay smoke and verify it succeeds while no worker browser window is visible |
| Hidden runtime auth loss is surfaced as manual reauth plus runtime-reliability review, not auto-window launch | HIDE-03 | Requires live failure or simulated auth tail | Force or observe a hidden worker returning `reauth_required`/`bootstrap_auth_required` and confirm internal admin plus logs do not auto-open a window and instead instruct manual review |
