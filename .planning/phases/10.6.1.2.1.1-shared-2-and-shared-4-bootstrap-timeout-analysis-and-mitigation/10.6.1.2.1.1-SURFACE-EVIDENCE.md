# Surface Evidence

- Date: 2026-03-30
- Scope: `shared-2`, `shared-4`
- Runtime: `host_visible_compact`

## Initial Failure Classification

Both workers originally failed local compact-visible proof with:

- `bootstrapResult = failed`
- `bootstrapFailureCode = worker_chat_bootstrap_timeout`
- `runtimeCapability = reachable_but_unusable`

## Captured Browser Surface

Live CDP inspection on both workers showed the same blocking surface:

- `url = https://chatgpt.com/`
- `title = ChatGPT`
- visible modal heading equivalent to `Теперь у ChatGPT есть память`
- visible dialog buttons `Включить` and `Не сейчас`

After dismissing that modal, the next captured surface on `shared-2` showed:

- `url = https://chatgpt.com/`
- no dialog present
- visible button with `aria-label="Включить временный чат"`
- normal composer/home surface already present

## Evidence Verdict

The original timeout was not caused by:

- dead profiles
- expired login
- Cloudflare challenge

It was caused by a two-step bootstrap gap:

1. A blocking memory dialog intercepted the initial bootstrap surface.
2. After the dialog was dismissed, the `Temporary Chat` entry still existed only through an `aria-label` path that the bootstrap runner did not yet recognize.
