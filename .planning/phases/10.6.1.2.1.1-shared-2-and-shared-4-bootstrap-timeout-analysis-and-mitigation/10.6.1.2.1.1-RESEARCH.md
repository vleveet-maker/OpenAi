# Phase 10.6.1.2.1.1 Research

## Existing Failure Boundary

`worker_chat_bootstrap_timeout` currently comes from `services/control-api/src/chat/worker-chat-bootstrap-client.ts`.

That timeout means:

- `control-api` reached the worker
- `/internal/chat/bootstrap` did not complete within 20 seconds

So this phase should focus first on:

1. what the worker-side bootstrap runner is doing during that window
2. what browser surface `shared-2` and `shared-4` are actually on
3. whether the issue is a new UI branch, popup, stale tab, timing branch, or per-profile surface state

## Existing Test Surface

`workers/agent/test/temporary-chat-runner.test.ts` already covers multiple `Temporary Chat` branches. That is the most natural place to add targeted regression tests once the repeated timeout branch is understood.

## Research Conclusion

This phase needs:

- one evidence-capture path for the two failing profiles
- one bounded mitigation in the bootstrap runner or worker recovery path
- targeted tests for the branch we identify
