# Phase 10.5 Plan 02: Summary

Alternate-desktop validation is now a real control-plane flow instead of a shell-only maintainer habit.

## Accomplishments

- Added `POST /workers/:id/validate-alternate-desktop` to the host-controller.
- Added `validateAlternateDesktop(workerId)` to the control-api host-controller client.
- Added `POST /internal/workers/:id/validate-runtime` so internal admin can validate the current non-visible runtime directly.
- Added `Validate non-visible runtime` to the operator admin page.
- Taught control-api to translate validation results into worker truth such as `runtimeCapability`, `lastBootstrap*`, and `reauth_required` for explicit auth loss.

## Key Decisions

- Keep validation in the host-controller because the proof depends on host-only scripts and Windows runtime facts.
- Keep validation synchronous in this phase so the operator sees a single truth-producing action before Phase 11 planning resumes.

## Verification

- `cmd /c npm.cmd test --prefix services/host-controller`
- `cmd /c npm.cmd test --prefix services/control-api`
- `cmd /c npm.cmd run build --prefix services/control-api`

## Residual Risk

- Long-lived validation requests are now routed correctly, but worker proof can still surface auth loss or scheduler/assignment noise that later phases must absorb explicitly.
