## Summary

This phase no longer means "put browsers on Linux".

That path was tried and then explicitly reverted. The replacement is a separate `Windows browser block`:

- Linux keeps `owmcgp-remote-relay` and the public API edge
- Windows holds `host-controller`, seven durable browser profiles, and reverse tunnels
- manual login and reauth happen only on the Windows side

## Locked Decisions

- Do not move browser runtime to Linux in this phase.
- Do not build around CAPTCHA bypass or anti-detection tooling.
- Keep Linux as the public relay/API edge.
- Treat the Windows block as a separate deployable module for Windows Server.
- Keep routine browser mode `compact visible` until a different runtime is proven.
- Use interactive Windows logon/session startup for GUI browsers; do not rely on Windows service Session 0 for browser login.
- Keep secrets, passwords, bearer tokens, and SSH keys out of tracked repo files.

## Phase Goal

Prepare and then execute a deployment path where the browser runtime can leave the current operator PC and move to a dedicated Windows Server block without changing the public Linux API contract.
