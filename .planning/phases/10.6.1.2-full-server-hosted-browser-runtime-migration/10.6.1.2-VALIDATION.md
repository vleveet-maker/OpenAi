# Phase 10.6.1.2 Validation

## Scope Check

This phase is valid only if it packages the browser runtime as a dedicated Windows block.

This phase is invalid if it:

- tries to put browsers back onto Linux
- treats server relay/API work as a substitute for runtime migration
- claims all seven accounts are good without a fresh worker matrix

- Windows block deployment doc:
  - [windows-browser-block.md](d:/OpenAi/docs/windows-browser-block.md)

  - [infra/windows-block](d:/OpenAi/infra/windows-block)
- updated remote relay docs that describe the Windows block honestly:
  - [remote-relay-server.md](d:/OpenAi/docs/remote-relay-server.md)
- current worker matrix:
  - [10.6.1.2-CURRENT-WINDOWS-BLOCK-MATRIX.md](d:/OpenAi/.planning/phases/10.6.1.2-full-server-hosted-browser-runtime-migration/10.6.1.2-CURRENT-WINDOWS-BLOCK-MATRIX.md)

## What Must Be True Before Closeout

- deployment prep exists for a dedicated Windows Server block
- Linux relay/API still keeps the deliberate public contract
- the seven-worker runtime no longer depends conceptually on "this operator laptop", even if the actual cutover is still being executed
- direct worker truth is explicit for all seven workers
