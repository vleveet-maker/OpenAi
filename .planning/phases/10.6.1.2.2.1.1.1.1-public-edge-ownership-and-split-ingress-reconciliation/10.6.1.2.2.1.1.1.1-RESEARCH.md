# Phase 10.6.1.2.2.1.1.1.1 Research

## Findings

### 1. The blocker is now ownership, not Windows-edge capability

The previous phase already proved that the preserved Windows edge still works locally.

That means the next phase should not spend its energy re-proving:

- worker runtime
- account validity
- Windows-side local API correctness

Those are now baseline truths.

The missing truth is different:

- which infrastructure layer actually owns public `77.66.186.75`
- whether that owner is supposed to forward to Windows `Caddy`
- or whether Ubuntu `nginx` is intentionally or accidentally still the public owner

### 2. Split ingress can fail long before any chat request

The decisive signal from the previous phase was not a chat failure first. It was this:

- `healthz` and `v1/models` already returned the wrong responder

That means the first-class proof path now has to begin with ownership and routing truth, not with canary chat calls.

If the public edge still lands on the wrong owner, outside chat proof is premature and should be rejected as non-authoritative.

### 3. Reconciliation may be safest through one deliberate owner, not necessarily direct Windows exposure

This phase should not assume the correct answer is automatically:

- public IP directly to Windows

The preserve-first answer may instead be:

- keep Ubuntu as the deliberate public owner, but make it reverse proxy to Windows cleanly
- or retarget MikroTik/public routing directly to Windows if that is the intended shape

The phase should stay outcome-oriented:

- one public owner
- one truthful contract
- one exact rollback path

### 4. Preserve-first still means canary-only worker proof

Even after ownership is reconciled, the worker-backed proof should still remain:

- canary-only
- `shared-6`
- no broad worker churn

The reason is unchanged: browser accounts are valuable and already deployed.

### 5. The phase should end with infrastructure truth strong enough to unblock or hold Phase 11

This follow-up is successful only if it removes the infrastructure ambiguity.

After it finishes, the project should know one of these exactly:

- Windows is the true public owner now
- Ubuntu is the true public owner and deliberately proxies to Windows
- an upstream or ownership split still blocks the final contract

That final truth, not just a new probe log, is what should control whether `Phase 11` resumes.

## Planning Implications

- Add dedicated requirement IDs for ownership map, deliberate-owner reconciliation, canary proof, and final verdict.
- Treat `healthz` and `v1/models` as ownership proof before chat proof.
- Prefer one deliberate public owner over a dual-owner or partially switched state.
- Keep changes bounded to ingress ownership, reverse-proxy handoff, and preserve-first proof tooling.
- Record exact blocker classes if the owner cannot be reconciled safely.

## Recommended Execution Order

1. Capture exact ownership truth across public IP, MikroTik/NAT, Ubuntu `nginx`, and Windows `Caddy`.
2. Choose one deliberate public owner path and reconcile it preserve-first.
3. Re-run canary-only external proof against that owner path.
4. Write one final verdict that explicitly controls whether `Phase 11` can resume.
