# Phase 10.6.1.2.2.1.1.1.1 Context

## Summary

This is the narrow preserve-first follow-up after the exact blocker was reduced to `public_edge_only`.

It is not a browser-runtime phase, not a login-recovery phase, and not another speculative TLS-only phase. The browser block and the preserved 9 accounts are no longer the main unknown. The unknown is now ownership of the public edge itself.

Previous phase `10.6.1.2.2.1.1.1` already proved:

- the preserved Windows `Caddy` edge is still healthy locally
- the 9 live accounts remained intact
- public `77.66.186.75` does not currently terminate on that Windows edge
- the public IP instead reaches Ubuntu `nginx` and returns `404`

So the next phase must answer one exact question:

- who really owns public `77.66.186.75`, and how should that ownership be reconciled without risking the preserved Windows browser block?

## Current Truth

- Preserved Windows browser block host: `192.168.88.250`
- Public IP under test: `77.66.186.75`
- Known competing public-edge responders:
  - Ubuntu `nginx`
  - Windows `Caddy`
- The intended safe Windows-side API topology is still:
  - `Caddy -> 127.0.0.1:4011` for shadow
  - `Caddy -> 127.0.0.1:4010` for promoted
  - `4040` and worker-agent ports remain private
- The preserved Windows edge is locally healthy, but the public IP currently lands elsewhere.
- The remaining uncertainty is no longer runtime or account health; it is ingress ownership and routing split between upstream layers.

## Locked Decisions

- Do not mass-restart, mass-relogin, or broadly revalidate all 9 workers for this phase.
- Keep `shared-6` as the only default canary unless the public owner path itself proves that even canary worker proof is premature.
- Do not expose raw `4040` or worker-agent ports as part of any workaround.
- Do not "solve" the phase by moving public traffic blindly without first recording who currently owns it.
- If ownership reconciliation is still blocked upstream, prefer one exact blocker verdict over speculative edge rewrites on the Windows host.
- Preserve-first remains higher priority than speed to green.

## Phase Goal

End this phase with one truthful outcome:

- `safe_to_promote`
- `safe_but_hold`
- `hold_preserve_accounts`

The phase is successful if it leaves no ambiguity about:

1. who owns public `77.66.186.75`
2. whether that owner can safely serve the deliberate Windows-side API contract
3. whether `Phase 11` can finally resume or must remain blocked by an exact upstream/public-edge blocker
