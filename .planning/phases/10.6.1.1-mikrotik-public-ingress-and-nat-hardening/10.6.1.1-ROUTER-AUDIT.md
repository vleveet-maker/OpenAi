## NAT And Firewall Truth

Verified through `apply-mikrotik-public-ingress.ps1 -WhatIf` after the real apply:

- existing NAT for server SSH:
  - `dstnat tcp/2222 -> 192.168.88.2:22`
- deliberate relay ingress rule now present:
  - comment: `owmcgp-public-relay-http`
  - `dstnat tcp/80 in-interface-list=WAN -> 192.168.88.2:80`

The default firewall set did not need a custom forward exception beyond the existing NAT path for this proof.

## Public-IP Truth

- Outside clients now reach the server `nginx` edge on `http://77.66.186.75`
- Invalid bearer on `http://77.66.186.75/api/relay/health` returns the relay boundary `403 remote_relay_forbidden`
- Raw `:4010` is still intentionally not public

## Important Nuance

The server itself is on the router LAN. A server-side request to `http://77.66.186.75/...` can still see RouterOS-local behavior instead of proving WAN NAT. For this reason:

- server-local `127.0.0.1` and `127.0.0.1:8080` checks prove the service and `nginx`
- outside-client/operator checks prove real public ingress
