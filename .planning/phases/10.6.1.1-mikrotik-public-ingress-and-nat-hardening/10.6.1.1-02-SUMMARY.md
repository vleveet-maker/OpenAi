# Phase 10.6.1.1 Plan 02: Summary

The MikroTik edge is no longer ambiguous. One deliberate NAT rule now forwards public HTTP traffic to the relay edge, and router management is scoped back to the LAN.

## Accomplishments

- Applied `dstnat tcp/80 -> 192.168.88.2:80` with comment `owmcgp-public-relay-http`.
- Restricted RouterOS management services to `192.168.88.0/24`:
  - `ftp`
  - `telnet`
  - `ssh`
  - `www`
  - `winbox`
  - `api`
  - `api-ssl`
- Added a manual `.rsc` fallback for RouterOS-side application.

## Verification

- live `apply-mikrotik-public-ingress.ps1`
- live `apply-mikrotik-public-ingress.ps1 -WhatIf`

## Residual Note

The public IP root can still show RouterOS from the LAN side of the same router. That is not a hardening failure by itself; the success gate is outside-client reachability to the deliberate edge.
