# Phase 10.5.1.1 Plan 02: Summary

`dad` recovery and fresh-profile diagnostics now live inside the internal control plane instead of depending on loose operator memory.

## Accomplishments

- Added `diagnostic_fresh` worker start support in host-controller and wired it through the control-api client.
- Added one temporary fresh-profile branch that reuses a diagnostics directory and never overwrites the durable profile in place.
- Added `POST /internal/workers/:id/manual-auth/complete-and-validate` so visible auth can immediately restart alternate desktop and run validation in one step.
- Added `POST /internal/workers/:id/diagnostic-profile/start` so the operator can launch a fresh-profile diagnostic branch from the admin page.
- Updated the internal admin UI with `Complete login and validate`, `Start fresh-profile diagnostic`, and clear copy that the temporary profile does not delete the durable profile.
- Preserved truthful post-validation state by recording whether the result came from the normal durable path or the diagnostic profile path.

## Key Decisions

- Fresh-profile diagnostics stay internal-only and temporary; success there is evidence, not silent replacement of the durable profile.
- Validation truth must name whether it came from normal auth recovery or from a diagnostic branch, so rollout decisions stay honest.

## Residual Risk
