# Phase 10.6.1.2.2.1 Validation

## Validation Focus

This phase is valid only if it activates or rejects the Windows-side public API edge without putting the 9 live accounts at risk.

It is invalid if it:

- mass-restarts or mass-relogs the 9 workers as part of edge work
- changes `Caddy` or edge listeners without a backup and rollback path
- declares public API success based only on local `127.0.0.1` proof
- exposes `4040` or worker-agent ports as the public contract

## Required Evidence

- explicit Windows edge audit artifact
- backup path for current `Caddy` or edge config
- one shadow-path canary proof
- one promoted-edge outside-client proof or one precise blocker artifact
- final phase verification with verdict

## What Must Be True Before Closeout

- the current owner of `80/443/4010/4040` is documented truthfully
- one shadow path is proven before promoted cutover
- one deliberate promoted path exists or one exact blocker is recorded
- rollback to the pre-phase edge state is explicit
- the verdict says one of:
  - `safe_to_promote`
  - `safe_but_hold`
  - `hold_preserve_accounts`

- local edge audit on `192.168.88.250`
- local shadow probe via `127.0.0.1:4011` or equivalent
- local promoted-edge probe through the actual edge process
