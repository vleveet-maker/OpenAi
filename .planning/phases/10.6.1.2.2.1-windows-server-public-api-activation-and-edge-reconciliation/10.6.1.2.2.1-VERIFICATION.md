## Final Decision

Decision: `hold_preserve_accounts`

Why:

1. The 9 accounts on the deployed Windows Server are still the highest-value asset.
2. The repo now contains the right preserve-first edge scripts and docs.
3. The current public path still resolves into `Caddy` redirects and broken HTTPS rather than a proven API boundary.
4. This execution did not have a direct Windows-side `Caddy` admin action path, so a safe promoted-edge proof did not happen.
5. Promoting now would be a blind change against a live preserve-first host.
